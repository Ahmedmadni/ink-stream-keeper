# تصنيفات المهام وقوائم التحقق الفرعية

## التفعيل

بعد migrations السابقة، طبّق ملفي المهام بالترتيب في مشروع Supabase المرتبط بالتطبيق:

1. `supabase/migrations/20261011183000_task_categories_checklist_rollup.sql`
2. `supabase/migrations/20261017070000_task_parent_completion_guard.sql`

إذا لم تطبق تحديث النسخ الاحتياطية السابق بعد، يصبح الترتيب الكامل:

1. `20261011060000_memoflow_backups.sql`
2. `20261011183000_task_categories_checklist_rollup.sql`
3. `20261017070000_task_parent_completion_guard.sql`

لا تحذف هذه التحديثات بيانات حالية، ولا تنقل أو تكرر البنود القديمة. التحديث الأخير يمنع أي واجهة أو نسخة تطبيق قديمة من إنهاء المهمة الأساسية بينما لديها بنود غير مكتملة، ثم يصحح الحالات السابقة وفق البنود الموجودة.

## السلوك

- صفحة المهام تعرض التصنيفات كفلاتر وأقسام، مع عدد المهام داخل كل تصنيف.
- يمكن إنشاء تصنيف مثل «العمل» أو «تطوير المواقع» من صفحة المهام أو أثناء إنشاء المهمة.
- يمكن إدخال قائمة التحقق عند إنشاء المهمة، بندًا في كل سطر، ثم تعديلها داخل تفاصيل المهمة. تبقى بنود المهام في مستوى واحد لتكون واضحة على الهاتف.
- يظهر بجوار كل مهمة عدد البنود المنجزة وشريط التقدم.
- إذا كانت للمهمة بنود، تتحكم البنود في حالتها: اكتمالها جميعًا يكمل المهمة الأساسية؛ إعادة فتح بند تعيد فتح المهمة؛ إضافة بند جديد إلى مهمة مكتملة تعيد فتحها؛ حذف آخر بند يعيدها إلى مهمة مفتوحة بلا تقدم.
- زر إنجاز المهمة الأساسية يصبح غير قابل للتعديل عند وجود بنود، لتجنب حالة متعارضة. يبقى متاحًا للمهام البسيطة التي لا تحتوي بنودًا.
- قاعدة البيانات تفرض القاعدة نفسها؛ تحديث `done` أو `status` أو `progress` مباشرة لا يستطيع تجاوز البنود غير المكتملة.
- في المهمة المتكررة، اكتمال جميع البنود ينقل الموعد إلى الدورة التالية ويحافظ على فرق وقت التذكير، ثم يعيد فتح البنود للدورة الجديدة. التكرار الشهري يراعي نهاية الشهر بتوقيت الرياض.
- التصنيفات الحالية في MemoFlow مشتركة مع نظام التصنيفات القائم؛ لا ينشئ التحديث نسخة أخرى من التصنيف أو يحذف الاستخدامات القديمة.

## التحقق بعد SQL

```sql
select
  to_regprocedure('public.memoflow_sync_task_checklist(uuid,uuid)') is not null as rollup_ready,
  to_regprocedure('public.memoflow_next_task_time(timestamptz,text)') is not null as recurrence_ready,
  exists (
    select 1 from pg_trigger
    where tgname = 'memoflow_rollup_task_checklist' and not tgisinternal
  ) as rollup_trigger_ready,
  public.memoflow_task_completion_guard_v1() as parent_guard_ready;
```

يجب أن تكون القيم الأربع `true`. بعد ذلك أنشئ تصنيفًا ومهمة بها بندان، وأغلق البندين: ستنتقل المهمة إلى «المكتملة». أعد فتح بند واحد: ستعود إلى «غير المكتملة». ومحاولة تحديد المهمة الأساسية من البطاقة قبل إنهاء البنود يجب أن تكون معطلة.

## الاختبارات

اختبارات PostgreSQL تطبق جميع migrations الفعلية مع RLS، وتتحقق من الإكمال وإعادة الفتح والإضافة والحذف والتكرار الشهري ومنع الإكمال اليدوي المبكر ودعم البنود القديمة وعزل الحسابات وتنظيف البنود عند حذف المهمة. كما تختبر واجهة الهاتف التجميع حسب التصنيف، وعدّاد البنود، وقفل علامة المهمة الأساسية، وإكمال المهمة من قائمة التحقق، ونموذج الإنشاء.
